Good, that’s a precise answer—and it reveals an important design decision point.

const requireLogin = (req, res, next) => {

    if (!req.session || !req.session.user) {

        req.flash(
            'error',
            'You must be logged in to access that page.'
        );

        return res.redirect('/login');
    }

    next();
}; 
This middleware checks whether the user is authenticated before allowing access to protected routes. It verifies if req.session.user exists. If the user is not logged in, it redirects them to the login page and shows an error message. If the user is logged in, it calls next() to continue to the requested route.

AI
This is a straightforward and correct `requireLogin` middleware. You’re doing the essential check: verifying session state and blocking unauthenticated access early, which is exactly what middleware is good for.
